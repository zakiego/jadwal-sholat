# AGENTS.md

## Project overview

Jadwal Sholat is a prayer-times site for every Indonesian city and regency (514 kabupaten/kota) plus any coordinates worldwide. One Cloudflare Worker serves all of it:

- The website: `/` guesses the visitor's city from their IP, and `/$city` shows that city's day and month. Both render on the server.
- A JSON API under `/api/v1`, with the OpenAPI spec at `/openapi.json` and `llms.txt` at `/llms.txt`.
- An MCP server at `/mcp`. It's stateless Streamable HTTP with no auth.
- iCal feeds at `/api/v1/calendar/{city}.ics`.
- A plain-text view for `curl <host>/<city>`, in the style of wttr.in.

Prayer times are computed in the Worker. There's no upstream API at runtime.

Stack: TanStack Start (React 19, TanStack Router), Vite 8 with `@cloudflare/vite-plugin`, Tailwind CSS v4, shadcn/ui (`base-nova` style on `@base-ui/react`), zod, and `@modelcontextprotocol/sdk`. The package manager is pnpm.

## Setup and commands

```bash
pnpm i
pnpm dev              # vite dev on http://localhost:3000
pnpm exec tsc         # typecheck (tsconfig has noEmit)
pnpm og               # render OG images, icons and manifest into public/
pnpm build            # pnpm og, then vite build
pnpm preview          # build, then vite preview
pnpm cf-typegen       # regenerate worker-configuration.d.ts after changing wrangler.jsonc
pnpm validate         # compare our times with the official Kemenag schedule
```

- `public/` is gitignored because `scripts/og.mjs` generates all of it. Run `pnpm og` (or `pnpm build`) after changing colors in `src/styles.css`, city data, or the OG card layout.
- `pnpm validate` calls api.myquran.com with a 1.5 s delay per request, so it's slow on purpose. The arguments are optional: `<dates comma-separated> <city slugs comma-separated>`.
- No environment variables or secrets are needed. `wrangler.jsonc` has no bindings.
- `bash scripts/setup-worktree.sh` is what T3 Code runs when it creates a worktree: it installs from the lockfile. It doesn't run `pnpm og`, so a new worktree has no `public/` until you run it or build.
- `bash scripts/clean-worktree.sh` is what T3 Code runs when a thread settles: it deletes `node_modules` and build output in that worktree, and does nothing in the main checkout.
- The T3 actions are in `t3.json`. T3 runs a project's saved actions, not the file, so after a change to it, import them again in Settings > Projects > Actions.

## Testing

There's no test runner and no linter. Before you call a change done:

1. Run `pnpm exec tsc` and fix every error. The config is strict, with `noUnusedLocals` and `noUnusedParameters` on.
2. Run `pnpm build` when you touch routing, the server entry, scripts, or anything that runs at build time.
3. If you changed `src/lib/prayer/`, run `pnpm validate`. Every prayer should stay within 1 minute of Kemenag.
4. For UI changes, open a city page in dev with `?data=demo|worst|after-isha|polar` (dev-only, see `src/dev/break-ui.tsx`). It swaps in worst-case data: the longest regency name, the next prayer falling on tomorrow's Subuh, and polar nights with null times.
5. For API, MCP, or text-view changes, curl the dev server:

```bash
curl localhost:3000/banjarbaru        # text view triggers on CLI user agents
curl localhost:3000/api/v1/schedule/banjarbaru
curl localhost:3000/openapi.json
```

## Layout

- `src/server.ts` is the Worker entry. It handles the HTTP-to-HTTPS redirect (plain-text curl requests are exempt), `/mcp`, `/api`, `/openapi.json`, `robots.txt`, `sitemap.xml`, `llms.txt` and the curl text view. Anything else goes to TanStack Start.
- `src/server/`:
  - `api.ts` has the REST handlers.
  - `mcp.ts` has the MCP tools.
  - `openapi.ts` has the spec and `llmsTxt`.
  - `ical.ts`, `text.ts` and `resolve.ts` handle feeds, the text view, and parsing places and options from a request (IP geo, `lat`/`lng`, `method`, `asr`).
  - `fns.ts` holds the TanStack server functions that route loaders call.
- `src/lib/prayer/`:
  - `engine.ts` does the astronomy.
  - `methods.ts` defines the calculation methods (Kemenag is the default, alongside MWL, ISNA, Egypt, Makkah, Karachi, JAKIM, MUIS and Diyanet).
  - `schedule.ts` turns a place into a day or month schedule.
- `src/lib/cities.ts` handles city lookup and search over `src/data/cities.json`.
- `src/data/cities.json` is generated. Don't edit it by hand. Rebuild it with `scripts/build-cities.py <wilayah_level_1_2.sql> src/data/cities.json` from [cahyadsn/wilayah](https://github.com/cahyadsn/wilayah) (MIT), using `uv run`.
- `src/lib/site.ts` holds `SITE_NAME`, `SITE_URL`, `SITE_HOST` and `REPO_URL`. Use these and never hardcode the domain or the repo link. The custom domain itself is set in `wrangler.jsonc`.
- `src/lib/seo.ts` has `pageHead()`, the helper every route uses for title, description, canonical and OG tags.
- `src/routes/` contains `/` (`index.tsx`), `/$city`, `/docs` and `__root.tsx`. `src/routeTree.gen.ts` is generated by the router plugin, so don't edit it.
- `src/components/` holds the app components. `src/components/ui/` is shadcn: add components with `pnpm dlx shadcn@latest add <name>` rather than writing them by hand.
- `DESIGN.md` is the design contract and the log of design decisions. Read it before any visual change, and add a dated entry under Decisions when you make one.

## Code style

- TypeScript, ESM, strict mode. No semicolons, double quotes, 2-space indent. Long lines are fine.
- Import from `src` with the `@/` alias (`#/` also works).
- Use `import type` / `type` modifiers where needed, since `verbatimModuleSyntax` is on.
- Server-only code lives in `src/server/` and runs in the Worker. Pages get data through `createServerFn` in `src/server/fns.ts`, so they render without a loading state.
- Write short JSDoc comments that explain why, not what.
- Style with Tailwind utilities and the shadcn tokens in `src/styles.css`. Colors are oklch `:root` tokens, and `scripts/og.mjs` reads them, so the OG cards follow the theme.

## Copy and language

- The site is in Indonesian. The API, MCP, OpenAPI, developer docs (`/docs`) and code are in English. The exception is prayer display names: JSON keys are English (`fajr`, `isha`), and the `name` values stay Indonesian (`Subuh`, `Isya`).
- Headlines are one plain sentence. No emoji in the interface chrome. No mosque, calligraphy or decorative-gradient art (see `DESIGN.md`).
- The type is Golos Text for the site and JetBrains Mono for commands and code.

## Deploy

```bash
pnpm deploy           # pnpm build, then wrangler deploy
```

It deploys to Cloudflare Workers with the custom domain set in `wrangler.jsonc`. For your own copy, change that domain and `SITE_URL`/`SITE_HOST` in `src/lib/site.ts`. CI (`.github/workflows/ci.yml`) runs `pnpm exec tsc` and `pnpm build` on every PR and on `main`. Deploys are manual.

## Commits and PRs

- Use Conventional Commits, `type(scope): description`, lowercase and imperative, e.g. `fix(ui): drop the trailing period from the hero headline`.
- Keep commits small, one logical change each.
- Run `pnpm exec tsc` before committing. Run `pnpm build` too when the change affects the build.
